# 回顾与展望

> 这一节不学新东西, 就是回头快速梳理一遍, 再往前看看下一步能往哪走.

## 1. 我们基本学完了

恭喜, 走到这里, 这门课的主要内容你已经学完了. 从建第一个 repo, 到在自己电脑上用桌面工具管理它, 一路都做下来了.

这一节很轻松, 不做新操作, 就是把学过的东西快速过一遍, 让你心里有个整体的谱, 知道自己到底学了什么, 现在能做什么. 然后再往前看一眼, 告诉你想继续走还能往哪走.

---

## 2. 快速梳理

整门课其实就三块:

**第一块, GitHub 的基本操作 (01 到 05).**
建 repo, 在网页上改文件并 commit, 开 branch, 用 Pull Request 把 branch merge 回 main, 最后养成 "把一切都放到 GitHub 上" 的习惯. 这一块让你会用 GitHub 干活, 也理解了为什么贡献图是你最可信的简历.

**第二块, 掌控访问权 (06 到 08).**
建 private repo 把项目藏起来, 把对的人邀请成 collaborator 一起协作, 生成 access token 让程序能代表你操作. 一句话串起来: 你能精确地决定谁能看, 谁能改, 谁能代表你.

**第三块, 更顺手的工具 (09).**
用 GitHub Desktop 把整套操作从网页搬到本地. 这也是真实工作里几乎所有人的做法, 在自己电脑上写, 再同步到 GitHub.

就这些. 三块连起来, 你已经能把 GitHub 当作自己日常的主要工作区了.

---

## 3. 简单自查: 你现在应该都会了

对着下面几条问自己 "能不能说出怎么做", 都能点头, 就说明真学到手了:

- 从零建一个 repo, 在网页或本地改文件并 commit.
- 开 branch 做实验, 再用 PR 或本地 merge 合回 main.
- 建一个 private repo, 分得清什么该 public 什么该 private.
- 把一个人邀请成 collaborator.
- 生成并安全保存一个 access token, 需要时能撤销.
- 用 GitHub Desktop 在本地跑通 clone, commit, push 这套流程.

卡在哪条, 就回去把对应那一节再翻一遍. 全都会了的话, 那你已经具备了把 GitHub 当作个人主要工作区的全部能力, 这就够用了.

---

## 4. 展望: 跨出一个人这层, 会 PR 就够了

老实说, 你学到的是 "一个人用好 GitHub". 而 GitHub 真正的价值, 要等你从一个人走向和别人协作时才完全展开. 往外这一步有两条路, 它们常被混为一谈, 其实落在两个完全不同的轴上. 分清楚了, 你就不会走弯路.

**先说和同事协作, 也就是上班.** 你可能以为职场协作很高深, 其实恰恰相反: 从技术素养上讲, 它要求的东西并不多. 说白了, 你只要会开 PR (你在 04 节就已经会了), 就已经能跟一个团队协作了. 大家各开各的 branch, 改动通过 PR 让别人 review 过再合并, 底层还是你早就学过的 commit, branch, merge. 真正难的不是这套技术, 而是门槛: 你得先有一个团队, 而找到一份工作, 一个团队, 从来不是件容易的事.

**再说给开源社区贡献.** 这条路刚好反过来. 它对你综合素质的要求其实更高, 这一点很多人没意识到: 你要读懂别人的代码, 遵守项目的规范, 把改动讲清楚, 还要经得起素不相识的维护者的审阅. 但它几乎没有入门门槛: 全世界成千上万的开源项目就摊在 GitHub 上, 全是开放的, 不是封闭的环境. 你只要愿意动手, 随时随地都能 fork 一个下来练, 提个 PR 试试. 有那么多现成的东西给你练, 这是职场给不了的.

把这两条路摆在一起看, 结论有点反直觉, 但很实用:

- **如果你的目的是上班**, 门槛在 "找到团队", 技术素养的要求其实不高, 会 PR 就够了.
- **如果你的目的是练手, 提升自己**, 反而是开源更容易上手, 因为它没有门槛, 到处都是可以练的地方, 尽管它对水平的要求更高.

最后给一条诚实的边界: 真正大规模, 多人, 跨团队的协作, 比这门课复杂得多, 那是你真到了那个场景再学的东西, 现在不用急. 作为你自己的主要工作区, 你现在会的已经足够. 而一旦你想跨出 "一个人" 这一层, 无论是上班还是开源, 那把钥匙都是同一个, 会 PR. 而这, 你早就有了.

---

## 5. 拔高: 想更进一步, 往这几个方向走

如果你学出了兴趣, 想走得更远, 下面给你几个方向. 每个方向都配了可以直接拿去搜索引擎搜的关键字, 以及一句可以直接复制粘贴喂给 AI 的话, 让它带你深入. 不用都学, 挑你现在最想要的那个开始就好.

**方向一, 命令行 git CLI (最推荐的下一站).**
前面你一直用的是网页和 GitHub Desktop 这样的图形工具, 日常完全够用. 但要知道, 图形工具好用, 不代表 git CLI 没用了. 真正专业, 灵活, 能自动化的操作方式是命令行, 图形工具下面跑的其实也还是它.

- 搜索关键字: `git cli tutorial for beginners`, `git clone add commit push pull explained`.
- 喂给 AI 的话: 我已经会用 GitHub 网页和 GitHub Desktop 做 commit, branch, merge, 现在想学命令行 git. 请从最常用的 clone, add, commit, push, pull 讲起, 每个命令配一个小例子, 尽量用类比, 讲给一个不是程序员的人听.

**方向二, 和同事协作的 PR 与 code review 流程.**

- 搜索关键字: `github pull request review workflow`, `code review best practices for beginners`.
- 喂给 AI 的话: 我会自己开 PR 和 merge 了. 现在假设我要和几个同事在同一个 repo 上协作, 请讲讲一个健康的团队协作流程是怎样的, 特别是 PR 的 review, approve, request changes 这些环节, 以及怎么处理冲突.

**方向三, 给开源项目贡献.**

- 搜索关键字: `how to contribute to open source on github`, `github fork and pull request workflow`.
- 喂给 AI 的话: 我想第一次给一个 GitHub 上的开源项目贡献代码, 但我对这个项目没有写权限. 请一步步讲清 fork, 改动, 提 PR 的完整流程, 以及第一次贡献时该注意的礼仪和常见坑.

**方向四, 用 GitHub Actions 做自动化.**

- 搜索关键字: `github actions beginner tutorial`, `github actions ci cd example`.
- 喂给 AI 的话: 我理解了 token 是 "让程序代表我操作 GitHub" 的钥匙. 现在想了解 GitHub Actions, 让 GitHub 在我每次 push 之后自动帮我跑一些事情. 请用最简单的例子带我入门, 讲清它大概是怎么工作的.

---

## 6. 结课

这门课到这里就结束了, 但别把它当成 "学完了一个软件", 而是 "养成一个习惯的第一天". 从今天起, 每开始一件事先问自己一句: 这个能不能放到 GitHub 上做? 让绿点自然地长起来.

等哪天你想更进一步了, 回到上面挑一个方向走出去就是. 这门课到此结束, 但你和 GitHub 的关系, 才刚刚开始.
