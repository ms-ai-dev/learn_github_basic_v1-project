# Create a Private Repository and Verify It Is Hidden From the Outside World

## 1. Goal

Create a Private Repository with your own hands, and use an incognito window to verify that "the whole world really cannot see it." Through this task, you will build sound judgment about visibility: knowing what content should be public and what should be private, understanding how serious it is that a public leak is irreversible, and knowing how to switch visibility in Settings.

---

## 2. What to Do

1. Read this lesson's README and understand the real difference between public and private, as well as when to use private.
2. Follow the steps in Section 7 of the README to create a new repo, choose Private for visibility, and check Add a README.
3. After creating it, confirm that the badge shown next to the repo name is Private.
4. Copy this repo's URL, open it in your browser's incognito window, and confirm that it returns a 404 rather than your repo.
5. Go into Settings, General, scroll all the way down to the Danger Zone, find Change visibility, switch the repo to Public and back to Private, and watch the badge change.
6. Be able to explain in your own words: why you must not commit secrets into a public repo, and why public content cannot be pulled back once it leaks.

**Estimated time:** About 15 minutes

---

## 3. Checklist

- [ ] **Understand visibility**: after reading this lesson's README, you can explain the difference between public and private, and what each is suited to hold.
- [ ] **Created successfully**: you successfully created a Repository with Visibility set to Private.
- [ ] **Recognize the badge**: you saw the Private badge next to the repo name on the repo home page.
- [ ] **Verify hidden**: you opened this private repo's URL in an incognito window and confirmed it returns 404, so someone not logged in cannot see it.
- [ ] **Switch visibility**: in Settings, General, Danger Zone, you switched the repo once between Private and Public, and switched it back to Private.
- [ ] **Understand the security line**: you can explain why passwords, keys, and private keys, any kind of secret, must never go into a public repo.
- [ ] **Understand irreversibility**: you can explain why public content can never be deleted once it leaks (gets forked or mirrored).
