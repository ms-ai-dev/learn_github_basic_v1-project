# 看懂 Collaborator, 并把这根弦记在心里

## 1. 目标

读懂 collaborator 是什么, 会走添加协作者的每一步, 并把 "没有邀请就没有协作" 这根弦装进脑子里. 这一节不强制你现在就找人来练, 重点是理解清楚, 等将来真有协作需求 (导师, 同学, 你带的学生要进你的 repo) 的那天, 你知道该怎么做.

---

## 2. 要做的事情

1. 阅读本节 README, 理解 collaborator 是什么, 以及在个人 repo 里它默认同时拥有 Read 和 Write, 也就是对方能看也能改.
2. 记住添加路径: repo, Settings, 左侧 Access 下的 Collaborators, Add people.
3. 弄清邀请认的是对方精确的 GitHub username, 不是昵称也不是邮箱; 同时明白, 想被别人邀请就要主动把自己精确的 username 或主页链接告诉对方.
4. 弄清邀请要对方接受才生效, 接受前状态是 Pending invite.
5. 如果手头正好有愿意配合的同学或一个自己的小号, 可以照着 README 第 8 节实际邀请一次 (可选).
6. 记住一个结论: username 选定后就别乱改, 因为它写在你每一个仓库的 URL 里, 一改就可能让别人存过的地址和链接全部失效.

**预计用时:** 5 到 15 分钟

---

## 3. 检查清单

- [ ] **理解 Collaborator**: 能说清 collaborator 是什么, 以及个人 repo 里默认拥有 Read 加 Write 权限.
- [ ] **记住添加路径**: 能说出 repo, Settings, Access 下的 Collaborators, Add people 这条路径.
- [ ] **用对 username**: 知道邀请要用精确 username 而不是邮箱, 也知道要把自己的 username 或主页链接清楚地告诉想邀请你的人.
- [ ] **懂接受流程**: 能说清对方必须接受邀请后才正式成为 collaborator, 接受前是 Pending invite.
- [ ] **记住底线**: 能说清对 private repo 而言, 没有邀请别人就无法访问, 也无法协作.
- [ ] **(可选) 实操一次**: 有条件的话, 实际邀请过一个人并在列表里看到了 Pending invite.
- [ ] **知道别乱改 username**: 能说清 username 写在仓库 URL 里, 乱改会让别人存过的地址和链接失效.
