# 把一份真实文档搬上 GitHub 并读懂你的贡献图

## 1. 目标

完成一次从 "用 GitHub 交代码作业" 到 "用 GitHub 做所有事" 的观念转变. 你要读懂 GitHub contribution graph, 亲手把一个真实的非代码文档搬进自己的 repo, 并且能讲清楚为什么这种做法在 AI 时代比任何单项技术技能都更值钱.

---

## 2. 要做的事情

1. 完整读完本节 README, 特别是 GitHub 加 AI 和贡献图这两部分, 也别漏掉导师寄语.
2. 访问你自己的 GitHub 主页, 找到并探索你的 contribution graph, 点开一个绿色方块, 看那天你 commit 了什么.
3. 访问一位经验丰富的开发者或活跃开源贡献者的公开主页, 对比两张贡献图的密度和持续性.
4. 想一个你最近在 Word 或 Google Docs 里写的非代码文档, 上课笔记, 作业, 任何文本都行.
5. 在你自己的 repo 里创建一个有意义命名的新文件, 把这个文档的内容搬进去.
6. 提交时写一句有意义的 commit message, 不要用 update 或 add file 这种敷衍的字样.

**预计用时:** 15 到 30 分钟

---

## 3. 检查清单

- [ ] **读完整节**: 完整读完本节 README, 包含导师寄语部分.
- [ ] **探索贡献图**: 打开了自己的 contribution graph, 并点开一个绿色方块看到了那天的 commit 细节.
- [ ] **完成对比**: 与一位经验丰富的开发者的公开主页做了对比, 理解了这个差距是习惯而不是天赋.
- [ ] **搬入真实文档**: 把至少一个真实的非代码文档从 Word 或 Google Docs 搬进了自己的 repo.
- [ ] **有意义的 commit message**: 提交这个文档时配了一句有意义的 commit message, 而不是 update 或 add file.
- [ ] **能解释造假为何行不通**: 能说清楚为什么刷 commit 造假会适得其反, 而且很容易被识破.
- [ ] **能说出 GitHub 的优势**: 能说出至少两个 GitHub 优于 Word 或 Google Docs 做长期文档管理的理由.
