# 在 GitHub 网页端编辑文件: 你的云端文档编辑器

> 本节教你在自己的 repo 里直接用 GitHub 网页端浏览和编辑文件, 无需安装任何软件.

## 1. 概览

在上一节 (01 Create Repo), 你已经创建了属于自己的 repo, 里面有一个 README.md. 本节我们就在那个 repo 上练手. 你会发现 GitHub 网页端本身就是一个功能完整的文本编辑器. 打开浏览器, 点几下鼠标, 就能修改文件并把改动永久保存下来, 全程不用碰命令行, 也不用装任何工具.

---

## 2. 学习目标

重要文档只存在本地电脑上是有风险的. 电脑坏了, 文档就没了. 换一台电脑, 你又改不了它. 把重要文档放到 GitHub 上能一次性解决这些烦恼: 随时随地访问 (只要有浏览器, 任何设备都能看能改), 自动保存历史版本 (每次修改都有记录, 不怕改错), 也方便别人直接查看. 更好的消息是, 你不需要为此安装任何软件, GitHub 网页端就够用了.

学完这个 Task, 你将能够:

1. 看懂 Repository 页面的布局, 认识文件列表和内容预览区域.
2. 用两种方式 (直接点文件名, 或用 File Explorer) 打开一个文件.
3. 进入编辑模式修改文件内容, 并用 Commit Changes 把改动保存到 main 分支.

---

## 3. 前置知识

- 已经完成 01 Create Repo, 拥有一个自己的 repo, 且里面有一个 README.md.
- 会用浏览器登录你的 GitHub 账号.

---

## 4. 你将构建或学到什么

你将在自己的 repo 的 README.md 里加上一行你的名字, 并成功保存. 保存后, 这次改动会出现在文件的修改历史里, 带着你写的 Commit Message 和时间戳. 这就是你在 GitHub 上留下的第一次正式编辑记录.

---

## 5. 认识 Repository 页面

打开你的 repo, 你会看到一个类似文件夹的页面. 它主要分成两块.

**文件列表区域**: 页面中间是文件列表. 你可能会看到 `.gitignore` (系统文件, 现在可以忽略) 和 `README.md` (项目的说明文档, 通常是别人打开 repo 后第一个会看的文件). 每个文件名后面还显示它最近一次的修改说明 (Commit Message) 和修改时间.

![repo 页面的文件列表区域](../../img/01-Edit-Files/01-Edit-Files-1.png)

**文件内容预览区域**: 文件列表下方会自动展示 README 的内容. GitHub 很贴心, 会自动把 `README.md` 渲染成排版漂亮的格式, 而不是让你看原始文本.

---

## 6. 如何打开一个文件

打开文件有两种方式, 用哪种都行.

**方式一, 直接点文件名**: 在文件列表里点一下文件名 (比如 `README.md`), 页面就会跳到这个文件的详情页.

**方式二, 用 File Explorer 文件浏览器**: 点开任意文件后, 页面左侧会出现一个面板, 这就是 File Explorer. 它包含三样东西: 分支选择器 (显示 `main`, 也就是你当前所在的分支), 搜索框 (标着 "Go to file", 输入文件名就能快速定位), 以及完整的文件目录树. 当 repo 里文件很多时, 用搜索框查找会非常方便.

![File Explorer 文件浏览器面板](../../img/01-Edit-Files/01-Edit-Files-2.png)

---

## 7. 如何编辑文件

编辑一个文件分三步.

**第一步, 进入编辑模式**: 打开文件后, 你看到的是 Preview 模式 (也就是渲染后的漂亮格式). 在页面右上角找到铅笔图标 (Edit file 按钮, 它和 Raw, Blame 这些按钮在同一行), 点一下就切换到编辑模式.

![点铅笔图标进入编辑模式](../../img/01-Edit-Files/01-Edit-Files-3.png)

**第二步, 修改内容**: 编辑模式里有两个标签页. Edit 标签页显示原始的 Markdown 文本, 带行号, 你就在这里像用记事本一样改内容. Preview 标签页则能预览改完后的效果. 在 Edit 里放心地打字就好.

**第三步, 保存修改 (Commit Changes)**: 改完后, 点右上角绿色的 "Commit changes..." 按钮, 会弹出一个对话框. 对话框里有几处要注意:

- Commit message: 用一句话简短描述这次改了什么, 比如 "Update README with my name".
- Extended description: 可选的详细说明, 留空也没关系.
- 两个单选项: "Commit directly to the main branch" (选这个, 直接保存到主分支) 和 "Create a new branch..." (本节暂时不用管它).

确认选中的是 "Commit directly to the main branch", 然后点绿色的 "Commit changes" 按钮, 保存就完成了.

![Commit changes 对话框](../../img/01-Edit-Files/01-Edit-Files-4.png)

---

## 8. 关于 Branch, 本节先不用操心

你在保存对话框里看到的 branch (分支) 是 Git 的一个高级功能. 它允许很多人同时修改不同的版本而互不干扰. 不过本节你还完全不需要理解它. 你只要始终待在 `main` 分支上操作, 保存时选 "Commit directly to the main branch" 就对了. 后面的课 (03 Working with Git Branch) 会专门讲清楚 branch 是怎么回事.

---

## 9. 练习

### 练习 1: 在 README.md 里加上你的名字

**目标:** 在你自己的 repo 的 README.md 里添加一行你的名字, 并把改动保存到 main 分支.

**怎么做:**

1. 打开你在上一节创建的 repo.
2. 在文件列表里找到并点开 `README.md`.
3. 点右上角的铅笔图标, 进入编辑模式.
4. 在文件里加一行写上你的名字, 比如 "Maintained by John Smith".
5. 点 "Commit changes..." 按钮.
6. 在 Commit message 里填 "Add my name to README".
7. 确认选中 "Commit directly to the main branch".
8. 点绿色的 "Commit changes" 按钮保存.

**你会观察到:**

保存后, 页面会跳回文件详情页. 你能看到文件内容已经更新, 里面出现了你的名字. 页面顶部显示的正是你刚才写的 Commit Message, 修改时间显示为 "just now" 或 "1 minute ago".

> **关键洞见:** 每一次 Commit 都是一次带说明的存档. 写清楚 Commit Message, 未来的你 (和别人) 一眼就能看懂这次改了什么.

## 11. 导师寄语

**为什么这个练习重要:**

很多人对 GitHub 的第一印象是 "这是程序员用命令行的地方", 于是望而却步. 这一节想让你亲身体验到, 编辑一个文件其实和改一份在线文档一样简单. 一旦你迈出这一步, GitHub 就从一个陌生的工具, 变成了你随身携带的云端文档柜.

**关键洞见:**

- 你不需要装任何软件, 浏览器就是完整的编辑器.
- 改错了也不用怕, GitHub 保存了每一次修改的历史, 随时能翻回之前的版本.

**下一步:**

把你真正在乎的文档 (学习笔记, 简历草稿, 项目说明) 放一份到 GitHub 上, 以后就能随时随地打开修改, 而且每次改动都有据可查.

## 12. 速查

**编辑一个文件的三步:** 打开文件, 点右上角铅笔图标进入编辑模式, 改完点 "Commit changes..." 并选 "Commit directly to the main branch" 保存.

**常见问题:**

- 我能编辑任何文件吗? 只要你对这个 repo 有编辑权限, 就能编辑里面所有文件. 你自己的 repo 当然有权限.
- 改错了怎么办? 不用担心, GitHub 保存了每次修改的历史记录, 可以通过 History 查看并恢复之前的版本.
- 能在手机上编辑吗? 可以, GitHub 网页在手机浏览器上也能用. 但屏幕小, 重要的编辑还是建议在电脑上完成.

**关键文件:**

- `README.md`: 项目的说明文档, 本节练习就在它里面加上你的名字.
