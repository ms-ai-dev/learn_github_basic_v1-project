# 创建你的第一个 GitHub Repository: 数字项目的起点

> 从零创建一个属于你自己的 GitHub Repository, 并理解它为什么是现代团队协作的地基.

## 1. 概览

这是 "Learn GitHub Basics" 系列的第一节. 在这一节里, 你会亲手创建人生中第一个 GitHub Repository (下面简称 Repo), 并且弄清楚每一个创建选项到底在做什么.

有意思的地方在于, Repo 看上去只是一个网页上的文件夹, 但它其实是一整套工作方式的入口. 一旦你理解了它, 你看待 "一个项目" 的角度就会不一样. 本系列后面的四节 (编辑文件, 使用 Git Branch, 合并 Branch, 把所有东西放上 GitHub) 都会在你这一节创建的这个 Repo 上继续操作, 所以这一步是整条学习路径的地基.

---

## 2. 学习目标

想象一个很常见的场景. 你和几个同事要合写一份报告. 你写完初稿, 发给同事 A, A 改完发给 B, B 又发回给你, 你再改一版, 结果同事 C 昨天也在自己那边改了一版. 现在桌面上躺着五个文件, 名字全是 report-final, report-final-v2, report-final-real 之类, 没有人说得清 "到底哪个才是最新版". 这种混乱几乎每个团队都经历过.

Repo 就是为了解决这个问题而存在的. 它是一个共享的项目空间, 所有人在同一个地方工作, 所有修改都有记录. 学会用 Repo, 你掌握的不只是一个工具, 而是现代团队协作的核心技能. 无论你是写代码, 写文档, 还是管理任何数字资产, 这套思维都适用. 这就是为什么我们把它放在第一节.

学完这个 Task, 你将能够:

1. 用自己的话解释 Repository 是什么, 以及它和普通文件夹的区别.
2. 独立创建一个配置正确的 GitHub Repository.
3. 理解每一项创建配置 (visibility, README, .gitignore, license 等) 的作用, 并为自己的项目做出合理选择.

---

## 3. 前置知识

- 一个可以正常登录的 GitHub 账户.
- 一个现代浏览器 (本系列全程在网页端操作, 不需要安装任何软件).
- 会用浏览器打开网页和点击按钮, 不需要任何编程经验.

---

## 4. 你将构建或学到什么

完成这一节后, 你会拥有一个真实的, 属于你自己的 Private Repository. 它里面至少有一个自动生成的 README.md 文件, 你可以随时打开它的主页, 看到仓库名和 README 的内容. 这个 Repo 会成为你接下来几节课的 "工作台", 后面所有练习都在它上面进行.

---

## 5. 什么是 Repository

你可以把 Repository 理解成电脑里的一个文件夹, 但它要强大得多. 与其说它是文件夹, 不如说它是一个 "智能项目文件夹". 我们用一张对比表来看它强在哪里.

- 普通文件夹只能存文件, 而 Repo 既存文件, 又记录每一次修改的历史.
- 普通文件夹通常一个人用, 而 Repo 天生支持多人协作.
- 普通文件夹改错了很难恢复, 而 Repo 随时可以时光倒流回到之前任意一个版本.
- 普通文件夹不知道谁改了什么, 而 Repo 每一次修改都有清清楚楚的记录.

理解了这张表, 你就抓住了 Repo 的三个核心价值.

第一, 它是一个项目的容器. 一个网站的所有代码, 一份产品的文档和素材, 一个数据分析项目的脚本和报告, 都可以完整地装在一个 Repo 里.

第二, 它是团队协作的单位. 你可以邀请同事加入, GitHub 会记录谁改了什么; 当有人的修改和别人冲突时它会提醒你; 它还让你可以审查别人的修改.

第三, 它是权限管理的最小单位. 你可以精确控制谁能看 (Read), 谁能改 (Write), 谁能管理 (Admin). 比如实习生只能看不能改, 外部合作伙伴只能访问特定的项目.

---

## 6. 进入创建页面

在正式填表之前, 你得先找到创建入口. GitHub 提供了两种方式, 用哪种都行.

方式一, 看页面右上角, 你的头像旁边有一个 "+" 号图标, 点开下拉菜单, 选 "New repository".

方式二, 进入你的个人主页, 顶部有一个 "Repositories" 标签页, 点进去后, 右侧有一个绿色的 "New" 按钮.

不管走哪一条路, 你都会来到同一个页面, 标题写着 "Create a new repository". 接下来我们逐个字段填.

---

## 7. 填写基本信息

这一屏要填三样东西.

Owner (所有者). 这个下拉菜单显示这个 Repo 归谁所有. 如果你用的是个人账户, 这里就是你的用户名. 如果你属于某个 Organization, 你也可以选择把它建在组织名下.

Repository name (仓库名). 这是最需要养成好习惯的地方. 建议用小写字母, 单词之间用连字符 - 分隔, 不要用空格或下划线, 名字要简短但有描述性. 比如 my-first-project, data-analysis-2024, team-docs 都是好名字. 你输入的时候 GitHub 会自动检查这个名字是否可用, 如果可用, 旁边会显示一个绿色的勾和 "is available".

Description (描述). 这一项是可选的, 用一句话说明这个项目是做什么的. 虽然可以留空, 但还是建议填上, 以后你自己或别人看到列表时会一目了然.

---

## 8. 配置选项

再往下是 Configuration 部分, 也是最需要理解的一段. 下面这张图展示的就是这个配置区.

![Repository 创建时的 Configuration 配置区](../../img/02-Create-Repo/02-Create-Repo-1.png)

我们逐项来看.

Choose visibility (可见性). 有两个选项. Public 表示任何人都能看到, 适合开源项目. Private 表示只有你和你邀请的人能看到, 大多数工作项目都应该选这个. 这里推荐选 Private, 而且不用担心选错, 之后随时可以改成公开.

Start with a template (使用模板). 初学者保持默认的 No template 就好.

Add a README (添加 README). README 是一个用来介绍项目的特殊文件. 别人 (或者未来的你) 打开这个 Repo, 第一眼看到的就是它. 强烈推荐把这一项打开 (On), GitHub 会自动帮你创建一个 README.md, 里面已经有了以项目名为标题的内容, 之后你可以随意编辑.

Add .gitignore (添加 .gitignore). 这个文件用来告诉 Git 哪些文件不需要跟踪, 比如临时文件, 日志, 或者含有密码的配置. 下拉菜单里有 Python, Node, Java 等常见选项. 如果不确定, 可以选一个最接近你项目类型的, 或者暂时选 None.

Add license (添加许可证). 许可证决定别人可以怎样使用你的代码. 如果只是私有项目或学习项目, 通常不需要, 推荐选 No license.

---

## 9. 完成创建

三样信息填好, 配置也选好之后, 点击页面底部那个绿色的 "Create repository" 按钮.

页面会跳转到你这个新 Repo 的主页. 你会看到仓库名出现在左上角, README.md 的内容显示在页面中央. 如果你刚才选了 .gitignore, 那么在文件列表里也会看到那个 .gitignore 文件. 到这里, 你的第一个 Repo 就正式诞生了.

---

## 10. 练习

### 练习 1: 创建你自己的第一个 Private Repository

**目标:** 独立走完整个创建流程, 得到一个配置正确的 Private Repository.

**怎么做:**

1. 用第 6 节里的任一种方式进入 "Create a new repository" 页面.
2. 在 Repository name 里填一个名字, 建议用 your-name-first-repo 这种格式, 比如 john-first-repo.
3. 把 Visibility 设为 Private.
4. 勾选 Add a README.
5. 点击底部绿色的 "Create repository" 按钮.

**你会观察到:**

页面跳转到新 Repo 的主页, 左上角是你刚填的仓库名, 中央显示着 README.md 的内容, 文件列表里能看到 README.md 这个文件.

> **关键洞见:** 创建一个 Repo 用不到 5 分钟, 但这短短几步就把一个项目从 "散落的文件" 变成了 "有边界, 有历史, 可协作的空间".

---

## 11. 回顾: 我们学到了什么

- Repository 就是一个智能项目文件夹: 它存文件, 记录历史, 支持协作, 还能控制权限.
- 一个 Repo 对应一个项目, 这是最自然也最清晰的组织方式.
- 创建时 Private 是最稳妥的默认选择, 以后想公开随时能改.
- 一定要勾选 Add a README, 它是这个项目的门面.
- .gitignore 根据项目类型来选, 不确定就先 None.
- 命名习惯很重要: 小写字母加连字符, 简短而有描述性.

---

## 12. 导师寄语

**为什么这个练习重要:**

当你点下 "Create repository" 那一刻, 你其实不只是建了个文件夹, 你是在建立一种新的工作思维. 我把它叫做从 "文件思维" 到 "项目思维" 的转变. 所谓文件思维, 就是一堆文件散在电脑里, 改完发来发去, 没人知道哪个是最新版, 也没人知道谁改了什么, 项目一结束文件就散落各处再也找不齐. 而项目思维是这样的: 每个项目都有一个家, 也就是它的 Repository, 所有人都来这里工作, 每一次修改都可追溯, 可回退, 整个生命周期清清楚楚.

**关键洞见:**

- Repository 从来不只是程序员的工具. 产品经理用它管理产品文档, 需求和会议纪要; 数据分析师用它管理脚本, 报告和数据字典; 内容创作者用它管理草稿, 素材和发布记录; 项目经理用它管理计划, 进度和风险清单. 关键不在于你做什么工作, 而在于你是否需要协作和版本管理.
- 值得养成 "先建 Repo" 的习惯. 每开始一个新项目, 第一件事就是建一个 Repo, 不管这个项目多小. 好处是从第一天起就有清晰的边界, 所有文件从一开始就有版本记录, 随时可以邀请别人加入, 项目结束时你还留下了一份完整的历史档案.

**下一步:**

把这个习惯带到你真实的工作里. 下次有任何新想法或新任务, 别急着在桌面新建文件夹, 先建一个 Repo. 本系列的第二节会带你在这个 Repo 上编辑文件, 我们的旅程才刚刚开始.

---

## 13. 速查

**创建入口:** 右上角头像旁的 "+" 号, 选 New repository; 或个人主页 Repositories 标签页里的绿色 New 按钮.

**推荐配置:** Visibility 选 Private, 勾选 Add a README, .gitignore 按项目类型选或先 None, license 选 No license.

**命名规则:** 小写字母, 连字符分词, 无空格无下划线, 简短且有描述性 (如 my-first-project).

**关键文件:**

- `README.md`: 项目的门面, 别人打开 Repo 第一眼看到的内容.
- `.gitignore`: 告诉 Git 哪些文件不用跟踪 (可选).
