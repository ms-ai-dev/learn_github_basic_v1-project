# 认清 Repo 的归属, 会在 Organization 里找仓库

## 1. 目标

建立起 owner 这根弦: 看到一个仓库知道它属于谁, 找不到一个仓库知道该去哪找, 自己建一个仓库知道它会落在谁名下. 这一节不要求你创建或改动任何东西, 全部是打开来看一眼, 心里有数就够了.

---

## 2. 要做的事情

1. 阅读本节 README, 弄清一个 repo 的完整坐标是 owner 加仓库名, 也就是 `github.com/OWNER/REPO`.
2. 打开你自己的一个 repo 和一个知名开源项目, 分别读出地址栏里的 owner, 并点进 owner 主页看看它是个人账号还是 organization.
3. 点右上角头像, 选 Organizations, 看看自己加入了哪些组织. 一个都没有也正常, 记住这个入口即可.
4. 如果有, 进其中一个 organization, 点顶部 Repositories 标签, 用搜索框搜一个关键字, 感受一下靠搜索而不是靠翻.
5. 弄清一件事: 能打开某个仓库不等于你加入了那个组织, 你可能只是那一个仓库的 collaborator.
6. 在 GitHub Desktop 里 File, New Repository 随便建一个本地 repo, 点 Publish repository, 展开 Organization 下拉看一眼有哪些选项, 然后直接关掉, 不用真的发布.

**预计用时:** 15 分钟左右

---

## 3. 检查清单

- [ ] **理解仓库坐标**: 能说清仓库名本身不唯一, owner 加仓库名才唯一, 并能从一条 URL 里读出 owner.
- [ ] **理解 Organization**: 能用自己的话解释 organization 是一个能拥有仓库的账号, 以及它和个人账号的关系.
- [ ] **知道自己的列表只有自己**: 能说清个人 Repositories 列表只列你自己名下的仓库, 别人分享给你的不在这里.
- [ ] **会看自己的组织**: 找到了头像菜单里的 Organizations 入口, 知道自己目前属于哪些组织 (或确认一个都没有).
- [ ] **会在组织里找仓库**: 知道进 organization 的 Repositories 标签并用搜索框找仓库, 也知道地址是 `github.com/orgs/ORG_NAME/repositories`.
- [ ] **分得清访问与加入**: 能说清能打开一个仓库不等于加入了那个组织, 这时完整 URL 是唯一可靠的入口.
- [ ] **看过 owner 的选择**: 在 GitHub Desktop 的 Publish repository 窗口里看到过 Organization 下拉, 知道 None 表示发布到自己名下.
