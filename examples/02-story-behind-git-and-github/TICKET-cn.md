# 讲清 Git 和 GitHub 是什么, 以及这块舞台凭什么也属于你

## 1. 目标

这一节不动手, 但它不是可以跳过的闲篇. 后面每一节你都在用 Git 和 GitHub 这两样东西, 而绝大多数人从头到尾都没分清过它们. 这一趟要拿到三样东西: 那条分界线, 一笔账 (GitHub 凭什么让你免费用, 靠不靠得住), 以及一个立场 (这个平台的底子是作品加社交, 不是代码加社交, 所以你不搞技术也有资格站上去).

判据不是 "读完了", 而是**你能不能合上教程用自己的话把它讲出来**. 讲不出来就是没读进去, 回去再扫一遍对应的小节.

---

## 2. 要做的事情

1. 完整读一遍本节 README, 特别是 Git 的来历, GitHub 的来历, 两者的区别, 以及这块舞台不只属于技术人这四节.
2. 合上教程, 用一句话对自己复述 Git 是谁写的, 为什么写, 最特别的地方是什么, 再回去对照第 5, 6 节看漏了什么.
3. 打开 github.com 的 Pricing 页面, 只看 Free 那一档, 逐条扫一遍, 挑出至少一条你之前不知道自己能免费用的东西.
4. 用搜索框搜一个非代码类的关键字 (awesome, handbook, notes, book, curriculum 都行), 按 star 排序, 挑一个一行代码都没有的高 star 仓库点进去, 看它的 README, 文件列表和参与人数.
5. 在那个仓库里点进 Pull requests 标签打开一个, 看看一次改动是怎么被讨论和合并的, 再点开某个贡献者的主页看一眼他的贡献图.
6. 拿自己的情况想一遍并给出答案: 你手上有哪一类产出是可以落成文本的, 如果把它放进一个 public repo, 别人点进去会看到什么.
7. 再给自己一个答案: 如果哪天你要把项目从 GitHub 搬到别的平台, 什么东西带得走, 什么带不走.

**预计用时:** 25 分钟左右 (只读不做约 15 分钟)

---

## 3. 检查清单

- [ ] **讲得出 Git 的来历**: 能说清 Git 是 2005 年 Linus Torvalds 为了 Linux kernel 写的, 以及它当初要解决什么问题.
- [ ] **讲得出分布式的意义**: 能说清每个 clone 都带着完整历史, 因此断网能干活, 分支很便宜, 备份是天然的.
- [ ] **讲得出 GitHub 多做了什么**: 能说清 GitHub 把 Git 仓库搬上网并加上了社交属性, 且知道 Pull Request 是 GitHub 的发明而不是 Git 的功能.
- [ ] **分得清工具和平台**: 能用一句话说明 Git 管历史, GitHub 管这份历史放在哪以及别人怎么看见它, 并能举出至少一个同类平台.
- [ ] **算得清那笔账**: 能说出至少两条 GitHub 敢给这么多免费额度的商业理由.
- [ ] **看过免费档**: 打开过 Pricing 页面的 Free 那一档, 能举出一条自己之前不知道的免费权益.
- [ ] **说得清它为什么是敲门砖**: 能说出 repo 放作品加上 star, follow, 贡献图这套社交构造和代码无关, 以及为什么可点进去看过程的东西比简历上的形容词更有说服力.
- [ ] **找到过非代码仓库**: 打开过至少一个一行代码都没有的高 star 仓库, 并能说出自己手上哪类产出也能这样放.
- [ ] **知道两条边界**: 能说清为什么不该把 GitHub 当作唯一副本, 以及为什么敏感内容和大文件素材不该往 public repo 里塞.
