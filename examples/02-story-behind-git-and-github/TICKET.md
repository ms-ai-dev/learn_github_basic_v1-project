# Explain What Git and GitHub Are, and Why This Stage Is Yours Too

## 1. Goal

This lesson has nothing to click, but it is not filler you can skip. Every later lesson uses these two things, and most people never separate them. You are here for three takeaways: that dividing line, one balance sheet (why GitHub lets you use it for free, and how far that can be trusted), and one position (this platform is built on work plus social rather than code plus social, so you belong here even if you are not technical).

The bar is not "I read it." It is **whether you can close the tutorial and say it in your own words**. If you cannot, you did not take it in, so go back over the matching section.

---

## 2. What to Do

1. Read this lesson's README end to end, especially the origin of Git, the origin of GitHub, the section separating the two, and the section on why this stage is not just for technical people.
2. Close the tutorial and retell in one sentence who wrote Git, why, and what makes it distinctive, then compare against sections 5 and 6 to see what you left out.
3. Open the Pricing page on github.com, read only the Free column item by item, and pick out at least one thing you did not know you could use for free.
4. Search a non-code keyword (awesome, handbook, notes, book, curriculum all work), sort by stars, and open a high-star repository with no code in it at all, looking at its README, file list, and contributor count.
5. In that repository, open a pull request from the Pull requests tab to see how one change gets discussed and merged, then open a contributor's profile and look at their contribution graph.
6. Apply it to yourself and answer: which of your own output could land as text, and if you put it in a public repo, what would someone see when they clicked in.
7. Answer one more: if you had to move your projects off GitHub to another platform, what would travel with you and what would not.

**Estimated time:** about 25 minutes (about 15 if you only read)

---

## 3. Checklist

- [ ] **Can retell Git's origin**: You can say that Git was written in 2005 by Linus Torvalds for the Linux kernel, and what problem it was solving.
- [ ] **Can explain why distributed matters**: You can say that every clone carries the complete history, which is why you can work offline, why branches are cheap, and why backups happen naturally.
- [ ] **Can say what GitHub added**: You can explain that GitHub put Git repositories online and added a social layer, and you know the Pull Request is GitHub's invention rather than a Git feature.
- [ ] **Can separate tool from platform**: You can state in one sentence that Git manages the history while GitHub manages where it lives and how others see it, and you can name at least one alternative platform.
- [ ] **Can explain the economics**: You can give at least two business reasons GitHub can afford such a generous free tier.
- [ ] **Looked at the free tier**: You opened the Free column of the Pricing page and can name one benefit you did not know about.
- [ ] **Can explain the door-opener**: You can say that a repo holding your work plus stars, follows, and a contribution graph has nothing to do with code, and why something a person can click into and inspect beats adjectives on a resume.
- [ ] **Found a non-code repository**: You opened at least one high-star repository containing no code, and can say which of your own output could be kept the same way.
- [ ] **Knows the two boundaries**: You can say why GitHub should not be your only copy, and why sensitive content and large raw assets do not belong in a public repo.
