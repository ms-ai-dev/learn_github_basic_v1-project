# Run Through a Full Workflow Locally with GitHub Desktop

## 1. Goal

Using GitHub Desktop on your own computer, redo from start to finish everything you learned on the web. Through this task, you will truly understand how local and remote relate, and master the whole set of actions: clone, local commit, creating and switching branches, push, and a local merge.

---

## 2. What to Do

1. Read this lesson's README and get clear on what GitHub Desktop is and the difference between local and remote.
2. Install GitHub Desktop and sign in to your GitHub account.
3. Use GitHub Desktop to clone one of your own repos (the public practice repo you created earlier is recommended) to your computer. If you can't recall the name, take a look at github.com/USERNAME?tab=repositories (replace USERNAME with your username).
4. In the local folder, change a file in your editor, save, go back to GitHub Desktop, and make a commit.
5. Click Push origin to send the change to the remote, and confirm on the GitHub website that the change appeared.
6. Create and switch to a new branch, change something on it and commit, and feel the change appear and disappear as you switch branches.
7. Switch to main, use Choose a branch to merge into main to merge that branch in locally, then Push origin.

**Estimated time:** About 15 minutes

---

## 3. Checklist

- [ ] **Understand local and remote**: you can explain that local changes do not appear on the remote until you push.
- [ ] **Installed and signed in**: you installed GitHub Desktop and signed in to your GitHub account.
- [ ] **Clone succeeded**: you cloned one of your own repos locally and can see its files in the local folder.
- [ ] **Local commit**: you edited a file locally and made a commit in GitHub Desktop.
- [ ] **Push succeeded**: you pushed the local commit to the remote and confirmed the change on the GitHub website.
- [ ] **Create and switch branches**: you created a branch, made changes on it, and experienced the change appearing and disappearing as you switch branches.
- [ ] **Local merge**: without a PR, you merged a branch into main locally.
- [ ] **Understand local merge versus PR**: you can explain that a local merge has no review or record and suits solo work, while a PR has review and a paper trail and suits teams.
