# Complete the Whole Learn GitHub Basics Course

## 1. Goal

By finishing every Task in this course, you should end up with a complete feel for the basic GitHub workflow: not a pile of scattered buttons, but one line you can walk end to end on your own, from sorting out how Git and GitHub divide the work, through creating a repo, editing files, branches, and PRs, to controlling access and finally working locally with GitHub Desktop. By the end you should be able to say with confidence what you learned, what you can now do on your own, and where to go next, and you should no longer feel this platform belongs only to people who write code.

---

## 2. What to Do

1. Read the README at the repository root first, so you know how this course is meant to be read.
2. Go into examples and read in numbered order starting at 01. The first one is the index and gives you a map of the whole course.
3. For each one, read the README first, then work through its own TICKET item by item and confirm each. The whole middle stretch builds on the same repo of your own, so read them in order.
4. Read the final wrap-up Task and work out what you learned and where you could go next.

**Estimated time:** 3 to 4 hours, and splitting it across sessions is fine.

---

## 3. Checklist

- [ ] **Every Task done**: every Task's TICKET checklist under examples is checked off item by item.
- [ ] **Tool versus platform**: you can say in one sentence that Git manages the history while GitHub manages where it lives and how others see it.
- [ ] **Can reproduce it solo**: without the tutorial, you can run the create a repo, edit files, open a branch, merge with a PR flow from start to finish on your own.
- [ ] **Can explain the concepts**: you can explain in your own words what a repository, a branch, a Pull Request, public versus private, and an access token each solve.
- [ ] **Local workflow works**: you can clone, commit, and push locally with GitHub Desktop, and you know where the local and remote boundary sits.
- [ ] **Knows repository ownership**: given any repository you can name its owner, and you know to look inside an organization for repositories shared with you.

---

## 4. Key Capabilities

- Explain what Git and GitHub each are, how they divide the work, and why this place is not only for people who write code.
- Create and configure a Repository from scratch, and confirm its visibility from an incognito window.
- Edit files in the web UI and save them to main with a meaningful commit message.
- Open a branch to experiment safely, merge the result back into main with a Pull Request, and explain roughly what a conflict is.
- Judge whether content belongs public or private, and hold the line that secrets never enter a public repo.
- Invite a collaborator using their exact GitHub username.
- Generate a least-privilege access token, store it safely, and know it can be revoked in one click.
- Use GitHub Desktop to clone, commit, branch, push, and merge locally without a PR.
- Recognize that every repo sits under an owner, and find a given repository in an organization's repository list.
- Build the habit of putting all your work on GitHub, so the contribution graph becomes your most credible long-term record.
