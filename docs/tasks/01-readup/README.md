# Learn GitHub Basics Overview

> In one line: this course walks you through GitHub's basic workflow from zero, starting entirely in the browser and landing on GitHub Desktop locally. For the full pitch, see [README-ORIGINAL.md](README-ORIGINAL.md).

## 1. What This Course Is

GitHub is the industry standard for managing and collaborating on text. This course takes someone who has never touched GitHub and walks them, hands-on, through its core basic workflow, with no command line anywhere, so that by the end GitHub is their everyday primary workspace. It also deliberately does not assume you are a programmer: the opening lesson establishes that this platform is built on work plus social, which makes it useful to anyone who wants a record of what they have done and a place to show it.

This is a readup-style teaching repository: the whole repo is one course, and its content is split into numbered Tasks under [examples/](examples/). You don't read it like a thick book cover to cover. Just follow the "How to Read" path below, go through the Tasks one by one, and do each one's TICKET as you read.

---

## 2. How to Read

1. Go into [examples/](examples/) and read in numbered order starting at 01. The first one is the index, and it gives you a map of the whole course: which parts it breaks into and what order to take them in.
2. In each Task folder, read the README first (what it teaches and what it has you do), then follow its TICKET to complete "what to do" item by item, and use the checklist to verify you actually did it.
3. Finish one, then move to the next, until the last one (it helps you recap what you learned and points to where to go if you want to take it further).
4. What counts as done: every Task's TICKET checklist checks off, and you can run the core flow yourself without looking at the tutorial.

The Tasks build on each other: the whole middle stretch operates on the same repo of your own, adding one piece at a time. So read them in order rather than skipping around.

---

## 3. What You Can Do by the End

By the end, GitHub is no longer an unfamiliar programmer's tool but your default home for everyday collaboration and version control: you can independently create repos, edit files, work with branches and PRs, tell what belongs public versus private, bring the right people in to collaborate, let programs act for you via a token, work comfortably on your own machine with GitHub Desktop, and tell at a glance who a repository belongs to. More importantly, you now have a public, timestamped place to keep what you have done, and that record speaks louder than any self-introduction.
